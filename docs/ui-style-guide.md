# CampusTrace 页面外观与交互规范

## 目标

所有模块必须看起来属于同一个系统，并保持基本易用性。当前阶段优先完成业务和安全功能，不进行大规模视觉重构；模块全部集成后再统一做视觉收口。

## 设计原则

1. 复用公共布局和已有组件。
2. 不在单个模块中重新定义主色、字体和页面框架。
3. 模块专属样式限制在模块范围内。
4. 先保证信息清楚、状态明确、操作可发现，再考虑装饰效果。
5. 所有页面同时检查桌面和手机宽度。

## 视觉变量

公共变量位于 `public/assets/app.css` 的 `:root`。

| 用途 | 值 |
| --- | --- |
| 页面背景 | `#f0f5fa` |
| 内容面板 | `#ffffff` |
| 主色 | `#193667` |
| 正文色 | `#10264b` |
| 次要文字 | `#506078` |
| 边框 | `#d7e1ed` |
| 错误 | `#a42937` |
| 成功 | `#1f6b4f` |

不得在模块页面中硬编码另一套相似颜色。如果确实需要新颜色，先在公开 PR 中说明用途并更新公共变量。

## 页面结构

所有 HTML 页面通过 `app/views/layout.php` 输出：

1. 顶部品牌和导航。
2. 主内容区 `.page`。
3. 成功或错误提示 `.notice`。
4. 页脚安全说明。

模块页面只提供 `main` 内部内容，不重复输出 `html`、`head`、`body`、主色导航或页脚。

## 公共组件

必须优先使用：

| 组件 | 类名 | 用途 |
| --- | --- | --- |
| 内容面板 | `.panel` | 表单、详情、列表区块 |
| 主按钮 | `.button.button-primary` | 当前页主要操作 |
| 次按钮 | `.button.button-secondary` | 返回、取消、次要操作 |
| 表单字段 | `.form-field` | 标签和输入控件 |
| 提示 | `.notice.notice-success` / `.notice.notice-error` | 操作反馈 |
| 标签 | `.badge` | 帖子、认领、举报状态 |
| 元信息 | `.meta-list` | 地点、分类、发布者等 |

新增模块样式使用明确前缀，例如：

```text
.image-module-panel
.claim-review-list
.report-admin-table
```

不得用宽泛选择器覆盖所有按钮、输入框或表格。

## 状态表达

- 状态必须同时显示文字和颜色，不能只靠颜色区分。
- 寻物和招领使用不同标签。
- 开放、已解决、已下架、待审核、已批准、已拒绝使用固定文字。
- 用户不可用的操作应隐藏或禁用，但服务端权限检查不能省略。

## 表单和错误

- 输入框必须有可见标签。
- 错误提示应靠近对应字段，并在页面顶部提供整体提示。
- 成功操作后使用统一 flash 提示。
- 不在页面中显示数据库错误、文件路径或堆栈。
- 图片上传需要显示允许大小、允许格式和当前限制。

## 响应式

- 桌面端以内容面板和双列列表为主。
- 小于 760px 时，双列布局改为单列。
- 长标题、路径和错误信息使用 `overflow-wrap`，不得撑破页面。
- 表格需要外层滚动容器 `.table-wrap`。

## 模块开发阶段

每位成员只做：

- 复用现有组件。
- 补齐字段、状态和反馈。
- 添加少量模块专属样式。

暂不进行：

- 重做导航。
- 引入前端框架。
- 添加复杂动画。
- 更换字体体系。
- 大规模修改全局 CSS。

## 集成后统一美化

全部业务模块合入后，由整合负责人统一完成：

1. 页面留白和标题层级。
2. 列表、详情和表单的视觉一致性。
3. 图片卡片和认领操作区域。
4. 空状态、错误页和移动端细节。
5. 无障碍与键盘操作检查。

## 页面合并检查表

- [ ] 使用公共布局。
- [ ] 使用公共颜色和按钮。
- [ ] 包含空状态和错误状态。
- [ ] 状态标签有文字。
- [ ] 桌面和手机宽度均可用。
- [ ] 没有模块专属全局选择器。
- [ ] 没有把安全关键逻辑只放在前端。
