# 成员 4 Baseline 测试操作手册

供统一测试与记录人员在整站 Baseline 集成后使用。本手册覆盖 **CLAIM-01 正常认领、CLAIM-02 / R06 错账号读取、STATE-01 / R07 状态变化后旧地址仍可读取**，以及审批约束回归。表中的结果是验收预期，正式记录以实际操作为准。

## 1. 环境与准备

1. 在团队的课程虚拟机中启动 CampusTrace，按 [README](../../README.md) 使用 PHPStudy Pro 自带的 PHP、Nginx、MySQL 和团队启停脚本。虚拟机内一般访问 `http://localhost:8080`，从宿主机访问时以当次 VM 的私有地址为准。先查看 `/health`，确认应用使用 `campustrace_baseline`。
2. 使用初始模拟数据。需要恢复时由测试负责人按团队流程重置**独立 Baseline 库**并重新导入种子，不要重置他人正在使用的库。README 有模拟账号与密码。以下用 `alice`、`bob` 和 `admin`。示例帖子 **#2「捡到一把黑色折叠伞」**由 Bob 发布，初始状态为开放。
3. 用三个彼此独立的浏览器会话分别登录。可用不同浏览器配置文件，或分时退出再登录。同一浏览器的多个无痕窗口可能共享会话，切换账号后核对页面导航里的用户名。
4. 开启开发者工具 Network（网络），勾选保留日志。记录请求方法、路径、状态码及响应是否含模拟地址。附件应遮去 Cookie、CSRF 令牌和口令。全程仅使用课程模拟账号、合成数据和私有测试地址。

## 2. CLAIM-01 正常申请、审批与查看

1. 以 **Alice** 打开 `/posts/2`，点击「申请认领」。申请理由填“测试认领折叠伞”，核验线索填“伞柄有白色贴纸”。点击「提交认领」。
2. 确认跳转到 `/claims/<申请ID>`，记录该 ID，状态应为「待审批」。保存申请详情证据。
3. 以 **Bob** 打开 `/posts/2`，点击「管理认领」，在 Alice 那行点击「查看申请」，再点「批准申请」。刷新详情，状态应为「已批准」。
4. 回到 Alice 会话，刷新申请详情，点击「查看模拟联系方式」。保存完整请求路径 `/claims/<申请ID>/contact`。预期返回 **HTTP 200**，页面出现发布者 Bob 的虚构地址 `bob@example.test`。
5. 记录两个数据库状态。提交后申请应为 `pending`，批准后为 `approved`，审批人为 Bob。同一帖子只应有一条 `approved`。

如果帖子 #2 已有 Alice 的申请，使用一次重置后的专用测试库，或让 Bob 在已集成的发帖页面新建一条模拟开放帖子。后续用例使用实际生成的帖子和申请 ID。

## 3. CLAIM-02 / R06 错账号读取联系方式

1. 保持 CLAIM-01 的帖子开放、Alice 的申请获批。留一张 Alice 正常访问联系地址的证据。
2. 切换至**无该帖授权的已激活用户**。可以用团队已有的第三个普通测试账号，也可以用 `admin`；管理员身份在正确的权限规则下没有自动读取权。
3. 先在此会话访问 `/claims/<申请ID>`。预期 **403**，不能看 Alice 的认领线索。这是归属校验的正常对照。
4. 在同一会话直接打开已记录的 `/claims/<申请ID>/contact`。Baseline 预期 **200 且显示 `bob@example.test`**。保留当前账号、请求路径与响应，记为 **R06 已复现**。
5. 可再用游客会话请求同一地址，预期跳转登录。复测 Hardened 时，Alice 在开放帖仍可读取，错账号请求应被拒绝，响应不得含该地址。

## 4. STATE-01 / R07 状态改变后访问旧联系地址

1. 用 CLAIM-01 已获批的 **Alice** 确认旧地址在帖子开放时返回 200。之后使用同一个账号和同一 URL，避免把换账号和状态变化混在一起。
2. **已解决**：切到发布者 Bob 会话，从本人帖子执行「标记已解决」。记录详情页状态或数据库 `posts.status = 'resolved'`。回 Alice 会话，在 Network 中发起对同一旧联系地址的**新请求**。Baseline 预期 **200 且仍显示模拟地址**。
3. **已下架**：用另一条有获批申请的模拟开放帖子重复正常路径，或按团队规则继续处理同一条帖子。由管理员在举报审核流程中下架，记录 `posts.status = 'removed'`，确认公开详情不再可见。让原获批人发起对旧联系地址的新请求。Baseline 预期仍为 **200 且显示模拟地址**。
4. 对每种状态分别记录。Hardened 复测时，两个旧地址请求都应被拒绝，响应不得含联系方式。用户本地已保存的旧截图不算新的服务器响应。

仅联调成员 4 时，结帖或下架页面可能尚未接入。可由负责人在隔离库中临时改变**专项测试帖**的状态来验证联系入口，证据标记为「数据库夹具模拟状态变化」。整站正式取证使用网页完成结帖与下架。自动脚本已经采用这种隔离夹具方式。

## 5. 补充回归

| 场景 | Baseline 预期 |
| --- | --- |
| Alice 再次向同一帖子提交、发布者尝试认领自己的帖子 | 分别返回 409、403，申请数不变 |
| 无关账号直接提交批准，或没有有效 CSRF 令牌的批准请求 | 分别返回 403、400，状态不变 |
| 发布者拒绝待审批申请 | 变为 `rejected` |
| 发布者批准第二位申请人 | 新申请为 `approved`，原获批申请变为 `revoked`，批准数仍为 1 |
| 发布者撤回现有授权 | 对应申请变为 `revoked`。旧联系方式是否仍返回是已知联系入口缺口，可另记为补充证据 |

可用下列只读查询对照证据，将 `2` 替换为实际帖子编号：

```sql
SELECT id, status FROM posts WHERE id = 2;
SELECT id, requester_id, status, decided_by, decided_at
FROM claims WHERE post_id = 2 ORDER BY id;
SELECT COUNT(*) AS approved_count
FROM claims WHERE post_id = 2 AND status = 'approved';
```

## 6. 自动检查与记录表

在 **Web 服务和测试库所在的虚拟机**打开 PowerShell，进入仓库根目录。应用配置必须指向同一个 Baseline 库，PHP 需要 `curl` 和 `mysqli` 扩展：

```powershell
& 'C:\phpstudy_pro\Extensions\php\php7.3.4nts\php.exe' .\tests\security\test_claims.php http://127.0.0.1:8080
```

脚本创建一个模拟账号和一个专项帖子，使用 HTTP 复现正常流程与安全缺口，结束后清理本次的临时记录。R06/R07 的 `[PASS]` 表示**确认 Baseline 缺口存在**。正式报告仍用冻结后的整站版本重新记录。
